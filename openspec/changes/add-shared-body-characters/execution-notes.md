# Execution notes

These are local execution observations, not changes to requirements or acceptance criteria.

- Install an already built local wheel offline with a cache inside the owning writable run. For example, use `uv pip install --offline --no-deps --cache-dir <run>/uv-cache --target <run>/installed <wheel>`. Writing the default global cache has repeatedly caused sandbox permission failures and long pending escalation requests. A local cache avoids that unnecessary external write; it does not authorize network access or new dependencies.
- Build requirements already exist in the local cache. Preserve the pinned versions. Record the exact wheel byte hash, runtime manifest hash and imported module paths before testing.
- Put the candidate installation on the import path before the first HML import in a test harness, and assert the imported path before running tests. A successful run against a stale `.venv` package is not candidate evidence.
- Use a saved harness and a simple `uv run --no-sync python <harness>` invocation for supervised Blender work. The supervisor requires system process inspection unavailable in the sandbox; request escalation for that owning invocation. Avoid complex shell wrappers. Do not manually edit execution locks or kill an ambiguous process group.
- Host tests that exercise real process-group supervision have the same process-inspection requirement. Inspect the actual failure trace before blaming concurrent CPU-only verification. Earlier runtime subsets passed when their owning test invocation had system process inspection. Test workspaces and backend state must remain isolated.
- The documented whole-host suite requires both `HUMANMOTIONLIB_SOURCE_ROOT` and a fresh `HUMANMOTIONLIB_TEST_RUN_ROOT`. Set them in the saved harness before test loading, verify interpreter/package location, and keep external installation-only variables unset unless deliberately running that separate acceptance harness.
- Distinguish the prepared JSON file byte hash from its embedded `content_sha256` identity. Both may be recorded; they are intentionally different.
- Report a pending tool, approval, session identifier or quota error promptly. Do not wait silently. Root interruptions are not human withdrawal of authorization.
- Native generation under the frozen try70 package completed for all three statures in runs try79/try80/try81. Do not regenerate those outputs merely to inspect them. Verification must retain their generator identity and must not claim they were generated by a later verifier package.
- Gate 2, independent final review and cleanup remain pending. Preview images and process exit codes are not acceptance.
- Do not adapt old run harnesses by partial string replacement. Earlier retries missed f-string run labels and read stale inputs. Build an explicit table of resolved input/output paths, read the saved harness back, and assert each prepared seal and package manifest before launching any process. A fresh output directory does not correct a stale input path.
